# K‑11 项目现状

更新时间：2026‑08‑23

## 一句话判断

项目已经越过“课程作业原型”，进入“系统很多、内容不少、但尚未形成一条可反复完成的成品体验”的阶段。现在最危险的不是功能少，而是继续横向加功能，让现有系统、地图和结局永远无法一起封板。

## 实际框架

`ShooterGameMode / GameState / PlayerState` 负责会话规则；`ShooterCharacter` 承载玩家战斗与失谐相关状态；`WaveManager` 是守潮、生成、阶段推进和结算的主要编排器；`BoBAIDirector + BoBEnemy + DT_BoBEnemies` 组成敌人生态；HUD、商店/掉落、遗物、处刑者、CS‑07 和结局标记围绕这条主循环工作。主地图是 World Partition 的 `Lvl_Shooter`，K‑11 地形由 `Art/K11Pipeline` 生成并重导入。

当前代码已经表达出目标游戏的大部分系统，但 `WaveManager`、`ShooterCharacter`、`ShooterHUD` 都承担过多职责。此时全面重构会推迟可玩闭环；应先用明确接口把纵切片锁住，再拆编排、表现和持久化。

## 已证实

- UE 5.8 C++ Development Editor 构建成功；反射枚举默认值、错误的兄弟类 Cast、过时字体 API、5.7 IncludeOrder 已修正。
- 自动玩法验证 21 / 21：敌人表 22 行及资源、Tide 1、玩家、处刑者、CS‑07 阶段/抗性/计时均通过。
- K‑11 审计 15 / 16：几何源与 UE 同步、1702 根城市柱无重叠/倾斜/悬浮、墙高、台阶、天空开口、水位、材质范围、280 级坑梯、292 环逃生通道及其导航均通过。
- 地形生成源和 UE 脚本已从 Downloads 收回项目，不再依赖一个看不见的外部工作目录。

## 尚未证实或未完成

- 迷宫全量导航为 1650 / 1752（94%）；102 格散落在 26 个小岛。关键主链通，但地形尚不能封板。
- 没有完成一次从开局到结局、无控制台干预的整局录像与走测记录；自动测试通过不等于游戏节奏成立。
- 结局 1/2 的链路有实现痕迹，结局 3 和稳定的存档/解锁闭环仍需核实并补齐。
- 22 行敌人数据存在，不代表 22 个敌人都已达到可辨识、可反制、可展示的内容质量。
- 正式角色、处刑者表现、音频、反馈、UI 统一和性能预算尚未封板。
- 旧 `WB_Result` 与 Android 触屏 UI 有蓝图编译警告；它们不在 Windows 单机 P0，但应在清理旧原型时删除或隔离。

## 当前技术风险

- 8 月成果大部分未形成可回退的 Git 基线；这是最高的工程风险。验证后应分批提交，不能再堆一个“大提交”。
- `ShooterCharacter` 中的静态全局状态和结局标记可能跨重开残留；在做存档前必须统一会话重置与持久化边界。
- 地形碰撞使用高面数复杂碰撞，导航构建已有性能警告；迷宫应该拆出专用简化碰撞/导航面，而不是继续在视觉网格上补洞。
- K‑11 管线已经自包含，但部分脚本仍硬编码 `D:\BuildOrBust`，属于 P1 可移植性债务。

## 已淘汰的事实

“双人同场竞技、十波丧尸、Android 成品、课程作业”是历史原型，不再定义产品。旧文档已放到 `docs/history/`，保留是为了追溯，不是为了继续兼容所有旧目标。
