# K‑11 项目现状

更新时间：2026‑08‑24

## 一句话判断

项目已经越过“课程作业原型”，进入“系统很多、内容不少、但尚未形成一条可反复完成的成品体验”的阶段。现在最危险的不是功能少，而是继续横向加功能，让现有系统、地图和结局永远无法一起封板。

## 实际框架

`ShooterGameMode / GameState / PlayerState` 负责会话规则；`ShooterCharacter` 承载玩家战斗与失谐相关状态；`WaveManager` 是守潮、生成、阶段推进和结算的主要编排器；`BoBAIDirector + BoBEnemy + DT_BoBEnemies` 组成敌人生态；HUD、商店/掉落、遗物、处刑者、CS‑07 和结局标记围绕这条主循环工作。主地图是 World Partition 的 `Lvl_Shooter`，K‑11 地形由 `Art/K11Pipeline` 生成并重导入。

当前代码已经表达出目标游戏的大部分系统，但 `WaveManager`、`ShooterCharacter`、`ShooterHUD` 都承担过多职责。此时全面重构会推迟可玩循环；先把地图灰盒做成，再用明确接口锁住纵切片。

## 已证实

- UE 5.8 C++ Development Editor 构建成功；反射枚举默认值、错误的兄弟类 Cast、过时字体 API、5.7 IncludeOrder 已修正。
- 自动玩法验证 21 / 21：敌人表 22 行及资源、Tide 1、玩家、处刑者、CS‑07 阶段/抗性/计时均通过。
- K‑11 新灰盒审计 22 / 22：几何源与 UE 同步；负一层迷宫 2002 / 2002 格可达；280 级坑梯、254 环逃生地道、两个合法开口、闭合地表土体、904 个剖面填土单元和灰盒材质均通过。地道从迷宫到地表口的导航终点误差 51cm。出口四段地板支撑 4 / 4、两侧回填 8 / 8。
- 六个 `PlayerStart` 已重新贴合当前地表。PIE 开局实测角色位于 Z=267cm，速度为 0，未处于下落状态。
- 地形生成源和 UE 脚本已收回项目，不再依赖外部工作目录。

## 尚未证实或未完成

- 新灰盒采用三块地表区域：核心防守区、废墟搜刮区、岩溶险区。现有 107 个低模体块，含接受派泉谷旧址、六边形抵抗派旧城和三个前代外来者现场；路线边缘最小净距 1220cm。内部按信标盆地、干谷通道、泉眼遗址、节理高地、隐蔽出口五个地点组织。旧城市底盘、130 个旧模块和专用灯已从主地图移除。保留地表核心 → 天坑 → 地下迷宫 → 逃生通道 → 地表的垂直骨架，完整路线目标 20–30 分钟。
- 三块区域不是三套任意主题。地表必须保留文明形成前的地质痕迹，并让接受派旧址、抵抗派旧址和三个前代外来者现场在空间语法上可区分。
- 没有完成一次从开局到结局、无控制台干预的整局录像与走测记录；新灰盒通过前不进入一潮纵切片。
- 结局 1/2 的链路有实现痕迹，结局 3 和稳定的存档/解锁闭环仍需核实并补齐。
- 22 行敌人数据存在，不代表 22 个敌人都已达到可辨识、可反制、可展示的内容质量。
- 正式角色、处刑者表现、音频、反馈、UI 统一和性能预算尚未封板。
- 旧 `WB_Result` 与 Android 触屏 UI 有蓝图编译警告；它们不在 Windows 单机 P0，但应在清理旧原型时删除或隔离。

## 当前技术风险

- 地图仍缺真人完整走测。自动审计通过不等于 20–30 分钟的节奏、迷路率和战斗视线已经封板。
- `ShooterCharacter` 中的静态全局状态和结局标记可能跨重开残留；在做存档前必须统一会话重置与持久化边界。
- `K11_Surface` 仍以复杂碰撞参加导航导出，约 44 万三角。M1 可用，精细化前必须拆分并补简单碰撞，不能把它带进成品。`K11_SoilFill` 只负责编辑器剖面显示，禁止碰撞和导航。
- K‑11 的正式生成、重导入和审计入口已经自包含；旧试验脚本只作本地参考，不属于现行工具链。

## 已淘汰的事实

“双人同场竞技、十波丧尸、Android 成品、课程作业”是历史原型，不再定义产品。旧文档已放到 `docs/history/`，保留是为了追溯，不是为了继续兼容所有旧目标。
