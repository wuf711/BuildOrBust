# K‑11 落地路线图

原则只有一条：每一阶段都必须让“可完整玩一局”更近，不能用新增系统数量冒充进度。

## Gate 0：建立可信基线（已完成）

- 保留本次已通过的构建、21 项玩法测试和 16 项地形审计入口。
- 将当前未提交成果按“代码与配置 / K‑11 地形与地图 / 文档与管线”拆成可回退提交。
- 把项目路径硬编码集中到一个配置入口。

验收：新机器拉取 LFS 后能构建、跑测试、生成并审计地形；工作区干净。

## M1：三块区域灰盒重做（自动验收完成，等待真人走测）

- 保留已经验通的地表核心、天坑、地下迷宫和逃生通道。旧地表外形退出封板状态。
- G0 核心防守区 `r 0–50m`：三条主要受敌方向；核心周围有完整环路、两档掩体、至少一条退路；地面起伏控制在 0–4m。
- G1 废墟搜刮区 `r 50–130m`：三条可辨识的搜刮分支；每条有一个主资源节点、一条回环或捷径、一个从核心可辨识的地标。
- G2 岩溶险区 `r 130–220m`：用峰丛、悬崖和干涸河谷收住地图边界；天坑放在高风险分支，逃生洞口保持隐蔽但可通过环境线索找到。
- 大区内部按五个支区组织：信标盆地、干谷抵抗线、泉谷接受派旧址、节理山脊、隐蔽返地口。支区边界跟随地貌和路线，不画新的同心环。
- 灰盒必须预留四层历史痕迹：文明形成前的岩溶地貌；G1 对称、完整的接受派旧址；通向天坑和 L2 的抵抗派加固旧址；三个既定坐标上的前代外来者小型现场。
- 先用灰盒体块、纯色材质和简化碰撞确定路线、尺度、遮挡、高差、战斗节点。灰盒通过前不搬正式建筑、不铺精细材质、不做装饰散布。
- M1 期间 `K11_Surface`、`K11_Underground`、`K11_F0Access` 统一使用灰盒网格材质。地表壳、地下地板和返地口短接坡必须是有厚度的闭合实体。
- 灰盒走测通过后，再进入模块化建筑、岩体、材质、灯光和叙事摆件的精细阶段。

验收：俯视图能直接读出三块区域；核心地面视角能识别至少两个远端地标；三条搜刮分支都能回到核心；不看文字也能区分接受派旧址、抵抗派旧址和前代外来者现场；完整路线 20–30 分钟；无软锁、碰撞卡死或必须跳跃才能通过的主路；关键路线录像；新版自动审计全部通过。

## M2：一潮纵切片

把一条真实循环做完整：简报 → 守潮 → 危险搜刮 → 带资源撤回/损失 → 商店与升级 → 下一潮。先只使用 4 个辨识度最高的敌人原型，锁定 20–30 分钟首局节奏、资源压力和失败原因。

验收：从新游戏到 Tide 2 无调试命令；失败和成功都能清楚解释；三名外部玩家能完成并复述循环。

## M3：敌人生态与导演

- 按“角色清晰度”而不是数据表行数扩充敌人：基础压迫、绕后、远程区域控制、重型破阵先成组。
- 让 AI Director 的调度可观察、可调参、可回放；避免与 WaveManager 争夺阶段权威。
- 再逐步启用 22 行敌人，并为每个敌人补齐辨识、反制、掉落和出场条件。

验收：连续三局的压力曲线不同但可解释；没有一种敌人靠纯数值承担全部难度。

## M4：中后局与标志性内容

完成 CS‑07 的可读阶段、抗性反馈、失败重试；补齐处刑者的正式视觉/音频、追猎和脱离反馈；把失谐/凝视与玩家决策真正绑定，而不是只做 HUD 数值。

验收：Boss 与处刑者各有一段无需解说也能看懂的作品集录像。

## M5：结局与持久化

明确三个结局的触发条件、冲突优先级和失败回退；完成结局 3；统一 SaveGame、会话重置、解锁和重开。删除散落在角色静态变量里的长期状态。

验收：从空存档分别走通三结局，重启程序后解锁保持，重开局不会继承临时状态。

## M6：作品集封板

统一正式 UI、字体、音频、角色与环境表现；做性能预算、崩溃与软锁测试；移除未引用的课程/Android/多人遗留；输出 Windows 包、预告片、玩法剪辑、技术拆解和项目说明。

验收：一份可下载完整作品、一段 60–90 秒预告、一段不剪辑完整流程、三篇能证明个人贡献的技术拆解。

## 明确不做

在单机作品封板前，不恢复联机目标，不维护 Android 成品承诺，不为“22 个敌人都存在”牺牲四个核心敌人的质量，也不进行与纵切片无关的全面 C++ 重构。
