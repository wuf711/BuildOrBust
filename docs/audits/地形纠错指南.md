# K-11 地形／负一层迷宫 — 系统性纠错指南

> 2026-08-12 现场审计。所有数字都来自 `Lvl_Shooter` 实测，不是生成器日志推算。
> 审计截图为本地诊断输出，不进入公共仓库。

## 一、最关键的问题

**关卡和生成器已经脱钩了。**

```
gen_k11.js 最后一次出图  ->  k11_surface.obj 等   2026-08-11 19:49
UE 里实际在跑的几何      ->  k11_surface.uasset 等 2026-08-11 07:29
                                                   差 12 小时 20 分
k11_water.uasset  2026-08-10 09:01   ->  比 obj 老了一整天
k11_hexcut.uasset 2026-08-11 02:48   ->  老 17 小时
```

逐个比对 OBJ 和 `.uasset` 的三角面数与包围盒之后，**真正没导进去的是三个**：

| 网格 | UE 里 | 磁盘 OBJ | 判定 |
|---|---|---|---|
| `k11_surface` | 264296 tris / ext 24750,23036,7096 | 一致 | 内容相同 |
| `k11_underground` | 26204 tris / ext 9950,9266,3700 | 一致 | 内容相同 |
| `k11_hexfield` | 54708 tris / ext 9732,9054,700 | 一致 | 内容相同 |
| `k11_f0access` | 6572 tris / ext 4228,**3451**,3270 | 7608 tris / ext 4256,**6681**,3168 | **差很多** |
| `k11_water` | 1830 tris / ext 5000,4000,0 | 2724 tris / ext 5200,6500,0 | **差** |
| `k11_hexcut` | 972 tris / ext …,**610** | 972 tris / ext …,**700** | **差（Z）** |

`k11_f0access` 的 Y 向尺寸从 3451 涨到 6681、面数 +1036 —— **这就是第 20 轮"逃生步道改直线"
那次重写，做完了，没导**。

所以准确的说法是：**地表/地下层/迷宫本体这三个大件内容是对得上的，脱钩发生在接驳通道、水面和
切割体上。** 但流程缺陷是一样的严重 —— 12 小时的分叉没有任何机制能发现，而且同一套缺陷在城柱
上造成的后果要大得多（见 2.2，两代同堂 3706 根）。

你反复说的"上一轮的问题解决得都很差""你遗失的太多了"因此是准确的，只是原因分两种：一部分修正
（逃生步道）真的没导；更多的（落地、受力、轮廓、坡度）是**在 JS 里断言通过，在 UE 里从来不成立**。

更要命的是验证方式。`maze_plan.png` 是 `dump_maze_png.js` 从生成器自己的内存数据画出来的，
证明的是**算法能生成完美迷宫**，和 UE 里有什么毫无关系。`[断言] PASS`、`[受力] 落地 1406 根`
这些也全是 JS 侧断言。**整个项目从头到尾没有一条断言打在 UE 上。** 自己验自己，闭环空转。

## 二、实测证据

### 2.1 山顶巨坑的"六边形阶梯"根本不存在

- `gen_k11.js` 里 **没有任何踏板生成代码**（全文搜 `hexplate`/`stair`/`tread` 零命中，只有一个
  叫 `riser` 的材质参数）
- 当时的地形应用步骤里 **没有任何摆放踏板的代码**
- 实际下坑路径是**刻进 `k11_surface` 高度场的一条光滑螺旋坡道**，不是台阶

坡道实测（沿导航路径量的，59 个路点，降 4559cm）：

| 段 | 平均坡度 | 换算 |
|---|---|---|
| 全程 | 27.6% | 15.4° |
| 底部 1/4（point 43-57） | 38~52% | 21~28° |

第 18 轮记的"坡度回到 8.3°"对不上，实测是它的近两倍，而且**越往下越陡**——半径在收缩，
每圈掉高不变，圆周越来越短。

`k11_hexplate` 这个网格（`gen_hexplate.js` 专门为阶梯做的）在关卡里有 **41 个实例，全部被
当成装饰石板乱扔在地表**：

```
BoB_Fill_F898   (17924, 21942, 6883)  scale (695.58, 293.76, 45.87)  yaw  83.4
BoB_Fill_F231   (-16694, 22145, 6459) scale (497.81, 700.68, 45.87)  yaw -26.7
BoB_Deco_Plate7 (-24555, 21021, 8332) scale (483.94, 541.98, 32.52)  yaw -34.8
```

非等比缩放（7:3 挤扁）、随机 yaw、而且刷的还是**第 1 轮就被你否掉的 `M_K11_Ground`**
（那个有 `.52 grey moss` 灰苔色阶的材质，全场还有 193 个 actor 在用）。

**并且：磁盘上没有任何脚本把 `k11_hexplate` 赋给这些 actor。** 全库搜 `hexplate`，只有
`gen_hexplate.js`（生成网格的）命中。也就是说这批改动是走桥的一次性 `run_python` 干的，
代码没落盘 —— 不可重跑、不可审查、不可回滚。

### 2.2 城柱：两代同堂，97% 没落地

`k11_hexprism` 共 **3706 个**，脚印尺寸分成泾渭分明的两族：

| 族 | scale.x | 数量 | 来源 |
|---|---|---|---|
| A | 211.5 | 1864 | 第 6/8 轮那版（散柱） |
| B | 185.0 | 1744 | 第 9 轮 `gen_cityvox.js`（按建筑轮廓栅格化） |
| O | 40 / 35 | 98 | `BoB_Seal` 封停件 |

**1744 正好是 `gen_cityvox.js` 的输出数。新一代加进来了，老一代一根没删。** A 和 B 之间实测
**214 处脚印重叠**（中心距 < 两柱内切圆半径和），这就是第 8 轮"乱摆的穿模了都"的直接原因——
当时的修法是**又生成一批**，不是**替换**。

落地情况（射线只打 `K11_Surface`/`K11_Underground`/`K11_F0Access`）：

```
总数 3706
  贴地（±50cm）      125   3.4%
  埋在地下          1907  51.5%
  悬空              1372  37.0%   中位 290cm，p90 1849cm，最大 5442cm
  底下压根没地形      302   8.1%
```

**最大一根悬在半空 54 米。** 第 10 轮那句 `[断言] 支撑者不足 2 根的悬空柱: 0 -> PASS`
在关卡里完全不成立。

另外 B 族里有 **350 根 roll/pitch ≠ 0**，直接违反第 9 轮你定的硬约束第 1 条
（"绝对禁止在 X 或 Y 轴上发生任何倾斜"）。

### 2.3 迷宫：不是迷宫，是一片乱石岗

把 `maze_plan.png`（生成器画的）和 `aud_maze_ortho.png`（UE 里正交俯视）并排看就明白了：
前者是一个漂亮的同心环六边形完美迷宫，后者是一堆高低不齐的六边形块，**没有任何可读的环和廊**。

在迷宫上打 9765 个垂直射线，相对走廊地面 -3680 的高差分布：

| 相对高度 | 样本 | 占比 | 判定 |
|---|---|---|---|
| -60cm | 3921 | 40.2% | 外圈地面（另一层地板） |
| 0 | 1073 | 11.0% | 走廊地面 |
| +120cm | 758 | 7.8% | **腰高，一眼望穿，不构成墙** |
| +240cm | 332 | 3.4% | 勉强算墙 |
| +300~480cm | 3622 | 37.1% | 正常墙 |

墙高被打散成 5 个档位、最低 120cm。**迷宫要成立靠的是"看不见下一个路口"，1.2 米的墙谁都能
看过去**，所以从任何视角都读不出迷宫。

**导航更糟。** 从迷宫入口出发，对 60 个随机走廊地面点做同步寻路：

```
可达 12 / 60      不可达 48     ->  80% 的迷宫走不到
```

部分路径全都卡死在几个固定边界上（`(-16500,-6500)` 18 次等），说明迷宫地面被切成了互不连通
的导航孤岛。

**根因是那个 60cm 的"视觉分层"**（记忆里记的"走廊地面比祭坛/死胡同低 60cm"）：

- `RecastNavMesh.AgentMaxStepHeight` 引擎默认 **35cm**
- `CharacterMovementComponent.MaxStepHeight` 引擎默认 **45cm**
- 工程里 `Config/*.ini` 和 `Source/` **都没有覆写**（已确认）

**60 > 45 > 35。** 这条 60cm 台阶对 AI 和玩家都是一堵看不见的墙。占地 40% 的 -3740 层和
占地 11% 的 -3680 层因此互相不可达，迷宫从这里就碎了。

### 2.4 一块孤儿水面漂在迷宫上方岩层里

```
K11_Water  世界包围盒 origin (-8840, -8400, -2980)  extent (5000, 4000, 0)
```

100m × 80m 的平面，**z = -2980**，正压在迷宫中心（祭坛在 -8880,-6144）上方。
迷宫地面 -3680/-3740，墙顶 -3420 —— 这块水面比墙顶还高 4.4 米，整个埋在实心岩里。
它是 08-10 那版地表湖的残留，`k11_water.obj` 已经重生成过，`.uasset` 没跟着导。

### 2.5 曝光和雾

```
BoB_ExposureLock  unbound  priority 100  HISTOGRAM  min=max=1.0  bias +1.2   <- 生效
PostProcessVolume unbound  priority   0  MANUAL     bias +0.35              <- 被压住的重复体
ExponentialHeightFog  actor z = -6850   density 0.03  falloff 0.12  volumetric extinction 2.5
```

- **两个 unbound PPV 打架**，低优先级那个是纯多余
- 曝光被锁死在一个按地表白天标定的值上。迷宫中心 32 盏补光叠上去 → `aud_maze_ortho.png`
  中心整块爆白；平视 → `aud_maze_eye.png` 一片没有细节的灰糊
- **雾的 actor 在 z=-6850**，高度衰减从那里算起。地下 -3680 处雾密度是地表 +2000 处的
  **约 1400 倍**，再乘 2.5 的体积雾消光 —— 地下能见度被雾吃光了

### 2.6 材质观感（`aud_city.png`）

地表读起来是**一地互不相连的白色六边形鳞片浮在深色光滑面上**，不是柱状节理玄武岩。
第 11 轮你说的"容易引起密恐"这个问题没解决，只是换了个尺度铺满了全图，连远山都是。

## 三、根因分解

上面六条不是六个独立 bug，是同一套流程缺陷的六个投影。

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | **导入不是幂等的** | 每轮"修复"是往关卡里**加**一批新 actor，老的不删。两代城柱同堂、41 个错位踏板、孤儿水面都是这么来的 |
| 2 | **验证闭环建在 JS 里** | `maze_plan.png` / `[断言] PASS` 全是自己验自己。UE 侧零断言，所以脱钩 12 小时没人发现 |
| 3 | **一次性 `run_python` 不落盘** | 关卡里相当一部分改动没有对应脚本（`hexplate` 赋值就是），不可重跑、不可审查、不可回滚 |
| 4 | **几何契约没写成可执行断言** | "落地""受力""坡度""墙高""只有两个通道"全是自然语言，没有一条能自动检出违反 |
| 5 | **导入顺序没有依赖图** | `k11_water`/`k11_hexcut` 停在两代之前，因为没人记得它们也要跟着重导 |
| 6 | **玩法参数没进几何设计** | 60cm 台阶是纯视觉决策，做的时候没人对过 `MaxStepHeight=45` / `AgentMaxStepHeight=35` |

## 四、纠错指南

### 步骤 0 · 先建 UE 侧审计，一行几何都别改

在没有"能打在 UE 上的断言"之前，任何重建都会重演同一个故事。

产出 `ue_audit_k11.py`，每条断言给出 PASS/FAIL + 实测数字：

| 断言 | 判据 | 当前 |
|---|---|---|
| `A1` 几何不陈旧 | 每个 `.uasset` 的 mtime ≥ 对应 `.obj` 的 mtime | **FAIL** 6 个 mtime 落后（其中 3 个内容真的不同） |
| `A2` 城柱单代 | `k11_hexprism` 的 scale.x 去重后只有 1 个非封停件取值 | **FAIL** 2 个 |
| `A3` 城柱不穿模 | 任意两柱中心距 ≥ 两内切圆半径和 | **FAIL** 214 处 |
| `A4` 城柱姿态 | roll = pitch = 0 | **FAIL** 350 根 |
| `A5` 城柱落地 | 底面到地形垂距 ∈ [-50, +50]，或在叠涩白名单内 | **FAIL** 仅 3.4% 通过 |
| `A6` 迷宫连通 | 从入口对 N 个走廊点寻路，可达率 = 100% | **FAIL** 20% |
| `A7` 墙高 | 所有迷宫墙相对邻接走廊 ≥ 240cm | **FAIL** 最低 120cm |
| `A8` 台阶可攀 | 任意相邻可行走面高差 ≤ 40cm | **FAIL** 存在 60cm |
| `A9` 只有两个通道 | 从 z=15000 垂直下打，能见到 z<-1200 的列 ⊆ {ENTRY, EXIT} | 需确认（现测到 5 列，2 处在 HexField） |
| `A10` 无孤儿几何 | 每个 K11 actor 的包围盒和至少一个可达空间相交 | **FAIL** K11_Water |

这份脚本就是后面每一步的验收标准。**在它全绿之前，不要相信任何"已修复"。**

### 步骤 1 · 给所有生成物打标签，把导入改成幂等

现在没法区分"这根柱子是第 6 轮的还是第 9 轮的"，只能靠 scale 反推。

1. 所有生成的 actor 加 tag `K11_GEN` + 一个批次 tag（如 `K11_CITYVOX_V3`）
2. 导入脚本第一步固定是：**按 tag 全删，再重建**。不做增量
3. 手工摆的东西（PlayerStart / 核心 / 刷怪点 / LootPickup）打 `K11_KEEP`，永不进删除集
4. 落盘：**桥上不再跑没保存的 `run_python`**。任何改关卡的代码先写成 `BoB_tools/*.py` 再执行

### 步骤 2 · 按依赖序整体重导一次

顺序有依赖，逐个来，每步跑一次步骤 0 的审计：

```
1  k11_f0access / k11_water / k11_hexcut  -> 必须重导（内容确实变了）
   k11_surface / k11_underground / k11_hexfield -> 内容一致，可以只对齐 mtime
   下次生成后仍然六个一起导，别再挑着导
   注意：f0access 的 Y 向从 3451 涨到 6681，重导后接驳通道位置会变，
        沿线的灯/封停件/拾取物要跟着重摆
2  材质分工复位   M_K11_Basalt -> Surface / Underground / F0Access
                 M_K11_MazeSplit -> 只有 HexField
                 M_K11_Ground -> 从 193 个 actor 上清掉
3  城柱          删光 3706 根，用 k11_cityvox.json 重摆 1744 根，射线只打上面 3 个地表 actor
4  迷宫布光 / 封停件
5  螺旋阶梯（见步骤 3）
6  重建 NavMesh，跑 A6
```

### 步骤 3 · 把螺旋阶梯真正做出来

这是设计里最重要的一条连接，现在是缺的。

- 在 `gen_k11.js` 里加 `writeStairPlates()`，输出踏板列表（圆心、半径、yaw、z），
  **不要再靠高度场刻坡道**
- 踏板用 `k11_hexplate`，**等比缩放**，yaw 量化到 30° 整数倍，相邻边贴合
- 单级抬升 ≤ **40cm**（低于 `MaxStepHeight` 45 留余量），踏面进深 ≥ 60cm
- 总降 4559cm ÷ 40cm = **≈114 级**；按 4.2 圈算每圈 27 级
- 踏板半径按当前坑半径的 32% 取、钳在 220..320（记忆里已定，别再用固定值）
- 走廊净宽 ≥ 200cm（`AgentRadius` 35×2 + 余量），外侧留矮沿防掉
- 摆完立刻验：相邻踏板高差 ≤ 40cm（A8）、踏板不啃坑壁（对坑壁做胶囊重叠测试）

顺手把那 41 个被挪用的 `k11_hexplate` 装饰全删掉，它们本来就是错的。

### 步骤 4 · 修迷宫的可读性和连通性

- **取消 60cm 视觉分层**。走廊/祭坛/死胡同的地面**做平**，靠材质、灯光、龛的高度差
  （墙上开龛，不是地面下沉）做区分。要保留高差就必须 ≤ 40cm，并且明确它是"可跨"而非"分层"
- **墙高统一到 ≥ 300cm**。现在 120/240 两档全部抬上去。迷宫的可玩性建立在遮挡上，
  高度参差 = 遮挡失效
- 重建 NavMesh 后 A6 必须 100%
- 中心祭坛、62 个死胡同藏物点逐个验可达（这是隐藏结局的解锁路径，一个不可达就断链）

### 步骤 5 · 视觉

按影响排序：

1. **删掉多余的 `PostProcessVolume`**（priority 0 那个），只留 `BoB_ExposureLock`
2. **地上地下分开曝光**。给迷宫加一个 bound 的 PPV（priority 200），单独标定；
   或者把 ExposureLock 改回 Auto 并收窄 min/max，别用 min=max=1.0 锁死
3. **雾的 actor 从 z=-6850 提到 z≈0**，重标 density；地下要雾就给迷宫单独放
   一个 `LocalFogVolume`，别让全局高度雾去管地下
4. 迷宫中心那 32 盏灯的强度按新曝光重调（现在爆白）
5. `M_K11_Basalt` 的六边形晶格：现在是**离散白鳞片浮在暗面上**，对比度和分布都不对。
   要的是柱状节理——**缝隙暗、柱面亮、缝隙连成网**。当前是反的（斑点亮、底暗、斑点互不相连），
   这正是"密恐"观感的来源
6. `M_K11_Ground` 清干净

## 五、验收

全部做完后，`ue_audit_k11.py` 的 A1–A10 必须全绿，并补三张对照图：

- `maze_plan.png`（生成器）vs UE 正交俯视 —— 环和廊要能一一对上
- 坑口俯视 —— 能数清台阶级数
- 迷宫平视 —— 看不到下一个路口

**只要这套断言还没打在 UE 上，就不要再宣布任何一条"已修复"。**
